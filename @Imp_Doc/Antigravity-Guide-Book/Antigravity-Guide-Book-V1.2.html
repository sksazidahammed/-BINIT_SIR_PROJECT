01 Overview & Architecture

Google Antigravity is an agentic development platform that ships as three surfaces: the Antigravity 2.0 desktop app for running agents, the Antigravity CLI (agy) for the terminal, and the Antigravity IDE — a VS Code fork with deep agent integration, plus extensions for VS Code, Visual Studio, JetBrains, Zed, and Xcode[reference:0].

Core Extension Primitives

PrimitiveWhat It DoesInvocation
Skill Modular package of domain knowledge, multi-step workflow, and optional helper scripts defined in SKILL.md. Teaches the agent how to orchestrate tools for complex tasks like incident triage or design-to-code. Auto-loaded on prompt match, or explicit /<skill-name>[reference:1]
MCP Server Connects agents to external APIs, databases, and dev tools via Model Context Protocol — remote HTTPS or local stdio. Declared in mcp_config.json; tools namespaced as <plugin>_<server>[reference:2]
Custom Agent / Subagent Specialized persona with dedicated system prompt, model tier, and tool allowlist; runs as primary session agent or background subagent. Defined in agents/<name>.md[reference:3]
Rule Persistent coding standards, architectural constraints, or glob-scoped instructions written in Markdown. rules/AGENTS.md or rules/*.md[reference:4]
Lifecycle Hook Synchronous shell command or prompt evaluation at specific loop points — SessionStart, PreToolUse, PostToolUse, PreInvocation, PostInvocation, Stop — to inspect, intercept, or augment agent behavior. hooks.json[reference:5]

Key design principle: Antigravity uses progressive disclosure — at session start only skill names and descriptions are loaded. Full SKILL.md instructions are pulled in only when relevant, keeping the context window lean[reference:6].

02 Install & First Run

Getting Antigravity

Download the desktop app from antigravity.google/docs/overview. The CLI (agy) is bundled or installable separately. For IDE extensions, see the extensions docs.

Project Structure

Antigravity reads skills from two locations[reference:7]:

# Workspace-level (per project)
.agents/skills/<skill-name>/SKILL.md

# Global (all projects, App + CLI)
~/.gemini/config/skills/<skill-name>/SKILL.md

# CLI-only skill locations
~/.gemini/antigravity-cli/skills/
~/.gemini/skills/

Important: The skill folder must sit directly under skills/. The .agent/skills path is legacy; .agents/skills is the current default[reference:8].

MCP Configuration Paths

# Global MCP config (recommended for API keys)
~/.gemini/config/mcp_config.json

# Workspace-level MCP config
.agents/mcp_config.json

# CLI MCP config
~/.gemini/antigravity-cli/mcp_config.json

You can open the MCP config directly from Antigravity UI: Settings → Customizations → Open MCP Config.

Quick Install: A Skill from GitHub

# Clone a skill collection into your workspace
git clone https://github.com/sickn33/antigravity-awesome-skills.git .agents/skills

# Or copy a single skill folder
cp -r /path/to/skill-folder .agents/skills/

The universal path that works across most tools is .agent/skills/; Antigravity officially defaults to .agents/skills/ but maintains backward compatibility[reference:10].

05 Plugins & Marketplace

The Antigravity Plugin Marketplace (launched October 2026) is a centralized catalog for discovering and installing verified plugins from Google and partners including Stripe, Figma, Jira, Datadog, and more[reference:23].

What a Plugin Bundles

A plugin is a versioned, self-contained directory defined by plugin.json that can package up to five component types[reference:24]:

Skills+ MCP Servers+ Custom Agents+ Rules+ Hooks

Plugin Manifest (plugin.json)

{
  "$schema": "https://antigravity.google/schemas/v1/plugin.json",
  "name": "my-plugin",
  "version": "1.0.0",
  "description": "Skills and specialized agents for my workflow",
  "author": "...",
  "components": {
    "skills": ["skills/code-review"],
    "mcpServers": ["mcp_config.json"],
    "agents": ["agents/reviewer.md"],
    "rules": ["rules/AGENTS.md"],
    "hooks": ["hooks/hooks.json"]
  }
}

Plugin Directory Structure

my-plugin/
├── plugin.json          # required manifest
├── skills/
│   └── code-review/
│       └── SKILL.md
├── agents/
│   └── reviewer.md
├── rules/
│   └── AGENTS.md
├── hooks/
│   └── hooks.json
└── mcp_config.json

Installing Plugins

# From marketplace (interactive)
agy plugin install <plugin-name>

# From GitHub
agy plugin install https://github.com/user/repo

# From local directory
agy plugin install ./my-plugin

Plugins are installed to ~/.gemini/config/plugins/. Skills inside plugins are namespaced by plugin name[reference:25].

Spotlight: The marketplace includes first-party integrations from software delivery, enterprise ops, data analytics, design, commerce, and security partners — browse categories in the Antigravity App under Customizations → Marketplace[reference:26].

06 Agents & Subagents

Antigravity lets you define custom agents (primary session personas) and subagents (background workers spawned by the primary agent). Both are Markdown files with YAML frontmatter specifying model, tools, and behavior.

Agent Definition Example

---
name: security-reviewer
description: Reviews code for security vulnerabilities
model: gemini-3-pro
tools: [read_file, list_directory, run_terminal]
---
You are a senior application security engineer.
Review every diff for injection flaws, auth bypasses, and secret leakage.
Report findings with severity, evidence, and remediation.

Runs in background—Yes
Parallel execution—Yes, via orchestration skills

07 Rules & Lifecycle Hooks

Rules — Persistent Guardrails

Rules are Markdown instructions that establish coding standards, API limits, security constraints, and domain conventions. They can be scoped globally or to specific file globs.

<!-- rules/AGENTS.md -->
# Engineering Rules

- All database queries must use parameterized statements.
- Never log secrets, tokens, or PII.
- API calls to third-party services must have a 10-second timeout.
- New endpoints require an accompanying integration test.
- Payment state must be verified server-side; never trust client-side flags.

Lifecycle Hooks — Deterministic Control

Hooks run outside the model’s reasoning loop and exchange structured JSON via stdin/stdout. They are your enforcement layer for security, auditing, and workflow gating[reference:29].

HookWhen It FiresUse Case
SessionStartNew session beginsInject workspace context, load environment info
PreToolUseBefore a tool is calledBlock dangerous commands, redact secrets, require approval
PostToolUseAfter a tool returnsAudit tool output, validate results, trigger follow-up checks
PreInvocationBefore model invocationInject context, modify prompts
PostInvocationAfter model responseFilter output, enforce formatting
StopAgent loop endsRun linters/tests; fail the turn if checks don’t pass

Hook Configuration (hooks.json)

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "run_terminal",
        "command": "node ./hooks/block-dangerous.js"
      }
    ],
    "Stop": [
      {
        "command": "npm run lint && npm run test",
        "failOnError": true
      }
    ]
  }
}

Team pattern: Use Stop hooks to require lint + tests to pass before the agent can complete a turn — a hard gate against shipping broken code[reference:30].

Safety Rails for Multi-Agent Work

  • Give each subagent the smallest tool scope necessary.
  • Use PreToolUse hooks to block consequential actions (deletes, spend, admin changes) without human confirmation.
  • Require Stop hooks to pass lint + tests before any agent claims completion.
  • Track processed event IDs / task IDs to make retries idempotent.

18 Troubleshooting

SymptomLikely CauseFix
Skill not loading Wrong directory or missing SKILL.md Verify path is exactly .agents/skills/<name>/SKILL.md. Check that the skill folder sits directly under skills/[reference:65].
MCP tools not appearing Config not loaded or invalid JSON Validate mcp_config.json syntax. Check global vs workspace path. Restart Antigravity after edits[reference:66].
Quota exhausted too fast High-capability model used for all tasks Route subagents and routine tasks to cheaper models. Install agy-usage or quotacli and set a PreInvocation warning hook[reference:67].

19 Best Practices — The Ten Rules

1. Start with a skill, not a prompt

If you repeat a workflow twice, package it as a skill. Skills are versionable, shareable, and progressively loaded.

2. Gate completion with Stop hooks

Require lint + tests to pass before the agent can finish a turn. Never trust “done” without verification.

3. Default-deny with PreToolUse

Block dangerous commands, secret reads, and unapproved external calls at the hook layer — outside the model’s reasoning loop.

4. Monitor quota from day one

Install agy-usage or quotacli. Route subagents to cheaper models. Quota resets every ~5 hours; don’t waste it.

5. Keep context lean

Progressive disclosure is a feature, not a bug. Deactivate skills you aren’t using. Prefer plugins over loose skill folders.

6. Separate planning from execution

Use brainstorming/grill-me skills to resolve ambiguity before code generation. Spec-driven development prevents rework.

7. Least-privilege agents

Every subagent gets the smallest tool allowlist possible. Consequential actions require confirmation hooks.

8. Audit before you ship

Run the 70-check security filter. Use debate-review skills on PRs. Scan for secrets in Git history and frontend bundles.

9. Cross-tool skill portability

Use .agent/skills/ for maximum compatibility across Claude Code, Cursor, Codex, and Antigravity.

10. Re-run the audit after meaningful changes

Auth, data, infrastructure, dependencies, payments, and AI tools change the risk surface. Re-audit, don’t assume.

Launch standard: Ship when relevant controls are verified with evidence, not when you have simply read the checklist. If you cannot point to the code, setting, config, test, or log that proves a guardrail exists, treat it as missing.
